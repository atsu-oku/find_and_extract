# find_and_extract.sh 運用ガイド

## 概要
`find_and_extract.sh` は、既存環境（現行基盤）と移行先環境（新基盤 STG／PRD）に関連する設定値を一括で洗い出し、変換し、必要に応じてロールバックできる Bash スクリプトです。標準の `scan` 動作に加えて、STG 向け設定の PRD 置換 (`transform`)、および変換ログを基にした復旧 (`rollback`) を実装しています。スクリプト実行時に生成されるすべてのログと一時ファイルは `/tmp/<ユーザー名>/<スクリプト名>` に集約されます。

主な特徴:
- Bash 4 以上で動作（起動時にバージョンチェックを実施）。
- 最大 1 MB までのテキストファイルを対象に Find/Replace や差分プレビューを提供。
- バイナリ／バックアップと推定されるファイルは自動スキップし、必要に応じて除外対象を拡張可能。
- 変換時は必ずバックアップを取得し、整合したロールバックログを併せて出力。

## 実行形式
```bash
./find_and_extract.sh [scan|transform|rollback] [オプション] <対象パス>
./find_and_extract.sh --deletelogs
```
*サブコマンド、省略時は `scan`。`--deletelogs` は単独指定。*

## サブコマンドと用途
| サブコマンド | 主な目的 | 代表的な出力 |
| --- | --- | --- |
| `scan` | ディレクトリ配下のファイルを走査し、現行／新基盤の判定条件に合致した箇所をログ化 | `*_current_infra.log`, `*_new_infra_stg.log`, `*_new_infra_prd.log`, `*_other.log` |
| `transform` | STG 由来の値を PRD 向けに置換。初期状態はドライランで差分のみ確認 | `*_transform_preview.log`（ドライラン時）, `*_transform.log`（適用時） |
| `rollback` | 変換ログ (`*_transform.log`) を読み取り、バックアップから対象ファイルを復元 | 復元状況サマリー（標準出力） |

## 共通オプション
- `-v`, `--verbose` : 進捗やスキップ理由、差分などの詳細ログを標準出力へ表示。
- `--skip-backup-files` : `*.bak`, `*.old`, `*~`, `.swp` など典型的なバックアップファイルを処理対象から除外。
- `--deletelogs` : カレントユーザー + ホスト名のログ一式を削除。確認プロンプト付き。
- `--apply` / `--dry-run` : `transform` 専用。`--dry-run`（既定）は変更を出力のみ、`--apply` は確認後に適用。
- `--file <パス>` : `rollback` で指定したファイルだけを復元（複数指定可）。

## `scan` モード詳細
1. **初期化と環境情報**
   - 実行時のホスト名・日時・スクリプトバージョンを各ログヘッダーに記録。
   - 標準出力にも同一ヘッダーを表示し、処理対象ディレクトリと出力先を案内。

2. **対象ファイルの抽出**
   - `find` により対象パス以下を列挙（`selinux` ディレクトリは除外）。
   - 1MB 超または `file(1)` でバイナリ判定されたファイルはスキップ。
   - `--skip-backup-files` 指定時はバックアップと推定される名前を除外。

3. **判定カテゴリと条件**
   - **現行基盤**: `100.100.x.x`、`172.16.0.0/17`、`10.0.x.x` 系などの IP 範囲、現行ホスト名プレフィックス、`iptp`、`pfs01` 等を検出。
   - **新基盤 STG**: `172.16.170-179.*` の IP、`newstaging`、末尾が `s` の新基盤用ホスト名パターン、単語としての `stg`。
   - **新基盤 PRD**: `172.16.160-169.*`、`newproduction`、末尾が `p` のホスト名、`git0<c>` 系ホスト、単語 `prd`。
   - **その他**: AWS／豊洲サイトのサブネット、`conv0`、`ipet-fs` 等の補足条件。

4. **ログ出力**
   - カテゴリごとにヒット行と前後 5 行のコンテキストを収集し、対応するログに追記。
   - 同一ファイルが複数カテゴリでヒットした場合は重複を避けて一覧化。
   - `--verbose` 指定時はファイル単位の判定結果を随時表示。

5. **スキャン結果サマリ**
   - 総走査ファイル数、カテゴリ別ヒットファイルを標準出力に整形表示。
   - 何もヒットしなかった場合は `該当なし` と明示。

## `transform` モード詳細
1. **事前チェック**
   - `/var` または配下を対象にした場合、`/var/www/com/ipet-ins/<system>/fuel/app/config/newproduction` の有無と `app.php` 等 5 ファイルを検証。欠損時は警告を記録。
   - 処理対象が `/var` 配下の Fuel/FuelPHP 設定ファイル以外の場合は自動でスキップ（誤変換防止）。

2. **ファイル処理フロー**
   - `scan` と同じ要領でファイルを列挙し、バイナリ／バックアップを除外。
   - 各ファイルに対し AWK スクリプトで置換を試行し、変更があった場合のみ一時ファイルと差分を記録。
   - ドライラン時は差分プレビューを標準出力に整形（`As-Is` / `To-Be` セクション）し、同内容を `*_transform_preview.log` に出力。

3. **適用 (`--apply`)**
   - すべての候補を一覧したのち、`yes` / `y` で確定。
   - 適用時は `*.bak_<timestamp>` のバックアップを作成し、元のパーミッション・所有権を再設定。
   - 書き換えが成功したファイルごとに `*_transform.log` へタブ区切りで記録（ヘッダー付き）。

4. **エラー処理と通知**
   - 変換に失敗したファイルは `失敗したファイル` セクションに列挙し、詳細メッセージを添付。
   - `td-agent` リポジトリ設定 (`/etc/yum.repos.d/td.repo`) については v4→v3 のフォールバック処理を内蔵し、結果を標準出力へ通知。
   - 途中で `Ctrl+C` を受けた場合は既存の一時ファイルを削除し、`処理を中断しました` と表示。

### 置換ルール一覧
| ルール | 適用条件 | 変換内容 | 例 |
| --- | --- | --- | --- |
| STG→PRD IPv4 | IPv4 / IPv4-CIDR トークンで第 3 オクテットが 170-179 | 第 3 オクテットから 10 を減算（サブネット表記があれば維持） | `172.16.175.0/24` → `172.16.165.0/24` |
| `/etc/profile` 特例 | 対象ファイルが `/etc/profile` で、第 3 オクテットが 173 | 第 3 オクテットを `162` に置換（第 4 オクテットは保持） | `172.16.173.8` → `172.16.162.8` |
| `0Ns` 表記 | `0` + 数字列 + `s` が単語として現れ、直後が英数字/`_` 以外 | `s` を `p` に置換し、桁構成はそのまま維持 | `01s` → `01p` |
| `Ns` 表記 | 任意の数字列 + `s` が単語として現れ、直後が英数字/`_` 以外 | `s` を `p` に置換 | `3s` → `3p` |
| `stg` トークン | 行頭が IP で始まる行／`Hostname=`／`PRETTY_HOSTNAME=` 行に含まれる単語としての `stg` | `prd` に置換（周囲が非英数字で区切られている場合のみ） | `Hostname=web-stg` → `Hostname=web-prd` |
| HTTPD 設定 | `/etc/httpd/` 配下または拡張子 `.conf` ファイル内の `newstaging` | `newproduction` に置換 | `SetEnv FUEL_ENV newstaging` → `SetEnv FUEL_ENV newproduction` |

補足:
- IP 置換では `127.0.0.1` / `::1` で始まる行を除外。IP トークン中に数字以外が含まれる場合や 0-255 以外の値は変換対象外です。
- `0Ns` / `Ns` 置換は隣接文字が英数字または `_` の場合はスキップされ、単語内部の `s` を誤変換しません。
- `stg` 置換は `staging` や `hostname_stg1` など単語内部に埋め込まれたケースは変換されません。
- いずれのルールでも変換が発生しなかったファイルは以降の適用フェーズに進みません。

備考:
- 行頭が `127.0.0.1` や `::1` のレコードは対象外。
- 置換後も差分が発生しなかった場合は適用候補から除外されます。
- 変換対象が 1 件もない場合は `変更対象のファイルは見つかりませんでした。` を表示。

## `rollback` モード詳細
1. **入力ログの検証**
   - 先頭行が `# original_path ...` のタブ区切り形式であることを前提に処理。
   - 欠落した行や存在しないバックアップファイルはその場で警告し、`Failed` カウントに加算。

2. **復元フロー**
   - バックアップ (`*.bak_<timestamp>`) を元ファイルへコピーし、元のパーミッション／所有者／グループを復元。
   - `--file` 指定がある場合は該当レコードのみ抽出し、見つからないエントリはエラー表示。
   - 完了後に `復元: X 件 / 失敗: Y 件` を出力。両方 0 の場合は `ロールバックログに復元対象がありません。` を表示。

3. **中断時の挙動**
   - 途中で割り込みを受けた場合は `処理を中断しました。` と明示し、ロールバック結果は得られません。

## ログと出力物
- すべて `/tmp/<ユーザー>/<スクリプト名>/` 配下に保存。ディレクトリは起動時に自動作成（700 パーミッション）。
- ファイル名は `<ホスト名>_<YYYYMMDD_HHMMSS>_種別.log`。主な種別:
  - `current_infra.log`, `new_infra_stg.log`, `new_infra_prd.log`, `other.log`
  - `transform_preview.log`（ドライラン） / `transform.log`（適用結果）
- `transform.log` の各行は `元ファイルパス`, `バックアップ`, `mode`, `uid`, `gid` をタブ区切りで保持し、`rollback` の入力として利用。
- `--deletelogs` は上記命名規則に合致するファイルのみ削除対象に含める。

## 運用時のチェックリスト
1. **事前準備**: Bash 4 以降であることを確認し、対象ディレクトリの読み取り権限を確保。
2. **スキャン**: `scan` → ログを確認し、置換範囲を把握。必要に応じて `--skip-backup-files` を付与。
3. **ドライラン**: `transform --dry-run` → 差分ログ (`*_transform_preview.log`) で置換内容をレビュー。
4. **適用**: 問題なければ `transform --apply` を実行し、生成された `*_transform.log` を保管。
5. **検証**: 変更後のサービスや設定ファイルを確認。必要に応じて `rollback` を準備。
6. **復旧**: 不備があれば `rollback <transform.log>` でバックアウト。
7. **後片付け**: 不要になったログを `--deletelogs` で整理。

## td-agent 設定ファイル生成スクリプト

環境変数 `TARGET_HOST` にホスト名（例: `line-lb01p`）を設定し、`generate_td_agent_conf.sh` を実行すると、サフィックスから役割 (`LB` / `AP` / `DB`) を判定し、対応するテンプレートをもとに td-agent 設定ファイルを生成します。

```bash
TARGET_HOST="line-lb01p" ./generate_td_agent_conf.sh
```

出力先: カレントディレクトリ (`td-agent_${TARGET_HOST}.conf`)

ホスト名プレフィックスと異なるドメインスラッグを使用したい場合は `SERVICE_SLUG_OVERRIDE` を上書き指定してください。

サフィックスから役割を特定できないホスト名の場合は警告を出しつつ、LB/AP/DB 全ブロックを包含した設定ファイルを生成します。

## トラブルシューティング
- **「ログを作成できません」エラー**: `/tmp/<ユーザー>/<スクリプト名>` に書き込み権限がない場合に発生します。空き容量とパーミッションを確認してください。
- **「変換対象がありませんでした」**: 置換ルールに該当する文字列がないか、既に PRD 値へ置換済みです。対象ディレクトリやファイル制限 (`/var` 配下フィルタ) を見直してください。
- **`td-agent` リポジトリ切替が失敗**: ネットワーク到達性の問題が考えられます。標準出力に記録されるメッセージ（v4→v3 フォールバック結果）を確認し、必要に応じて手動調整してください。
- **ロールバックでバックアップが見つからない**: 変換時に生成された `*.bak_<timestamp>` が削除されている可能性があります。ファイルを復元するか、バックアップ管理ポリシーを見直してください。

以上を踏まえ、`find_and_extract.sh` は STG→PRD 移行の判定・置換・復旧をワンストップで支援します。ログとバックアップを適切に管理し、ドライランで置換内容を必ず確認してから本適用を実施してください。
